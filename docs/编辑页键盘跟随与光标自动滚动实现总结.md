# 编辑页键盘跟随与光标自动滚动实现总结

日期：2026-10-19  
项目：随心记 Android App  
实现位置：`app/src/main/java/com/qiuyinlan/suixinji/NotesActivity.kt`，`QuickNoteEditor`

## 1. 目标与结果

编辑页需要同时满足两种行为：

1. 工具栏和新建加号是正文滚动区域之外的底部控件。键盘打开时，它们整体上移到键盘上沿；正文滚动不能把工具栏卷走。
2. 随着文字增加或连续换行，正文自动滚动，使当前光标和正在输入的文字保持在工具栏上方，并留出空白。

本次修改已构建成功并覆盖安装到连接的 vivo V2073A 手机。最终实机截图确认：键盘打开后，整条工具栏及右侧加号均完整显示在键盘上方，解决了之前被键盘遮挡的问题。

正文的显式光标跟随滚动逻辑也已实现。不过，本次自动操作未完成可靠的长文连续输入验证，因此不能把“工具栏定位验证成功”扩大为“所有输入场景均已验证成功”。长文本、连续换行、中文输入法组合输入仍需继续验收。

## 2. 原本为什么没有做好

### 2.1 只设置 adjustResize，不能证明工具栏会跟随键盘

早期使用全屏 Compose `Dialog`，设置 `decorFitsSystemWindows = true`，并通过窗口的 `SOFT_INPUT_ADJUST_RESIZE` 期待系统压缩页面。

虽然工具栏已经是正文下方的同级控件，但在这台手机的 Dialog 中，实际可用区域没有按预期缩小。键盘覆盖了窗口底部，工具栏仍停留在原来的底部位置，因此被遮住。

之后仅改为 Compose 的 IME Insets，实机仍能看到工具栏被遮挡。继续增加原生 `getRootWindowInsets()` 读取后，也没有单独解决这台设备上的问题。不能仅凭 API 已调用或 APK 构建成功认定布局已正确。

### 2.2 请求整个输入框可见，不等于请求光标可见

早期在文字长度或选区变化时调用 `BringIntoViewRequester.bringIntoView()`，目标是整个输入框，没有传入当前光标矩形。

当输入框本身已经铺满可见区域时，让整个控件可见并不能准确表达“把长文末尾的光标滚到工具栏上方”。

后来换成 `BasicTextField`，但仍依赖输入框的内部滚动行为，正文没有独立、明确的光标安全距离和滚动目标计算。这不足以保证用户要求的长文输入效果。

### 2.3 标签弹层布局回调引入额外更新

为定位 `#` 标签候选框，曾在每次文本布局时写入布局状态，造成不必要的重组。之后为了减少更新，又只在输入标签时记录布局，普通正文无法使用这份布局计算光标位置。

正确处理方式是记录当前正文对应的布局，仅在文本、布局尺寸或行数发生变化时更新，而不是无条件更新，也不是只为标签输入更新。

### 2.4 窗口坐标原点不一致会导致工具栏只露出一部分

兼容测量最初使用：

```text
遮挡高度 = 根视图高度 - 可见区域 bottom
```

但根视图高度是视图自身尺寸，可见区域的 bottom 使用屏幕坐标。忽略根视图在屏幕上的纵向偏移，会少算一段高度。实机表现是工具栏上移了，但下半部分仍被键盘遮住。

## 3. 现在如何实现工具栏跟随键盘

### 3.1 页面结构

```text
编辑页根容器：统一处理系统栏、键盘避让
└─ Column
   ├─ 顶部标题和操作
   ├─ 标签、时间、图片等信息
   ├─ 正文视口：weight(1f)
   │  ├─ 独立纵向滚动容器
   │  │  └─ BasicTextField：按正文内容增长
   │  └─ 标签候选覆盖层
   └─ 底部 dock：工具栏 + 新建加号
```

工具栏没有放入正文的 `verticalScroll`。工具栏与加号共用一行，因此根容器避让键盘时，两者一起上移。

### 3.2 统一处理 Insets，不把导航栏和键盘高度相加

Dialog 使用 `decorFitsSystemWindows = false`，并通过 `WindowCompat.setDecorFitsSystemWindows(window, false)` 配置窗口；同时保留 `SOFT_INPUT_ADJUST_RESIZE`。

根 `Surface` 使用：

```kotlin
Modifier.fillMaxSize().windowInsetsPadding(
    WindowInsets.systemBars
        .union(WindowInsets.ime)
        .union(WindowInsets(bottom = nativeImeBottom))
)
```

`union` 对每个方向取最大避让值，而不是把几种底部高度累加。这样系统栏和键盘高度不会重复叠加。

### 3.3 原生键盘 Insets 与可见窗口兼容测量

通过 `DisposableEffect(editorView)` 注册全局布局监听，在窗口可见范围改变时读取：

- `ViewCompat.getRootWindowInsets(editorView)` 中的 IME bottom。
- `getWindowVisibleDisplayFrame()` 返回的屏幕可见区域。
- 根视图尺寸及 `getLocationOnScreen()` 返回的屏幕坐标。

兼容计算为：

```text
根视图在屏幕上的底边 = rootView.height + rootLocationY
遮挡高度 = max(0, 根视图底边 - visibleFrame.bottom)
兼容键盘高度 = 遮挡高度 > 120dp 时取遮挡高度，否则取 0
最终原生键盘高度 = max(IME Insets bottom, 兼容键盘高度)
```

120dp 是用于排除小范围系统栏遮挡的经验阈值，并非 Android 的通用键盘高度标准。兼容逻辑用于当前设备全屏 Dialog 的 Insets 异常情况；后续应继续验证其他机型与浮动键盘模式。

`onDispose` 中移除监听，防止编辑页退出后继续持有监听。

## 4. 现在如何实现正文随光标自动滚动

### 4.1 让正文内容增长，而不是固定输入框内部滚动

正文视口使用 `weight(1f)` 占满标题与工具栏之间的剩余空间。视口内部增加 `verticalScroll(editorScroll)`，`BasicTextField` 使用 `fillMaxWidth()`，不再使用 `fillMaxSize()` 把自身固定为整个视口。

`maxLines` 从 30 调整为 `Int.MAX_VALUE`，由外层正文滚动容器承担长文滚动。文本底部增加 48dp 内边距，为末尾光标向上滚动提供余量。

### 4.2 获得准确光标位置

`onTextLayout` 保存当前 `TextLayoutResult`，同时记录它对应的原始正文，避免拿旧文本布局计算新文本光标。

由于 Markdown 转换会隐藏部分符号、插入评论标记，原始文本下标与显示下标并不相同。因此先通过当前 `VisualTransformation` 的 `OffsetMapping.originalToTransformed()` 转换光标下标，再调用 `getCursorRect()` 读取光标矩形。

### 4.3 根据视口计算滚动量

在文本布局、光标选区或正文视口高度变化时执行滚动检查。键盘打开导致视口变矮，也会触发重新检查。

```text
光标 top/bottom = 文本布局中的光标矩形 + 顶部 16dp 内边距
安全距离 = 32dp
可见底边 = 当前滚动量 + 视口高度 - 安全距离

若光标 bottom 超过可见底边：
    目标滚动量 = 光标 bottom - 视口高度 + 安全距离
若光标 top 小于当前滚动量：
    目标滚动量 = 光标 top
否则：
    保持当前滚动量
```

使用 `scrollTo()` 立即调整，避免连续换行时反复启动、取消动画导致光标追赶和拖延。滚动值下限为 0，上限交由 `ScrollState` 根据内容尺寸约束。

这段逻辑表达的是“让当前输入光标位于工具栏上方”，而不是简单地每输入一个字都滚到全文末尾，因此也考虑了用户返回正文前面编辑的情况。

## 5. 与标签候选框、性能的配合

标签候选仍是正文视口中的覆盖层，保留较高 `zIndex`，避免被输入框盖住。正文引入滚动后，候选框的纵向位置需要减去 `editorScroll.value`，使锚点跟随屏幕上实际显示的光标位置。

文本布局状态只在正文变化、布局尺寸变化或行数变化时更新；视口高度、编辑框坐标也避免重复写入相同值。

Markdown 评论标记此前对每个字符都扫描全部评论，现改为先按位置 `groupBy`，逐字符时直接查对应位置，减少重复扫描。

注意：连续换行是否流畅不能仅靠这些代码优化推断，仍需以实机输入和必要的性能测量为准。

后续验收应覆盖：键盘反复开关、长文末尾连续输入与换行、返回中间段落编辑、中文组合输入、撤销重做、格式按钮插入、标签提示、不同输入法及浮动键盘。

本次修复的关键是：工具栏避让使用真实窗口可见范围，正文跟随使用真实光标布局。两种机制分别负责各自的问题，不能用“工具栏在输入框下方”或“输入框自带滚动”代替实际验证。
