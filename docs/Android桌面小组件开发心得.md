# Android 桌面小组件开发心得

这份记录基于随心记的三个组件：随机漫步、快速新建笔记、收藏笔记。重点是避免“代码看起来写了，桌面却没显示或点了没反应”的情况。

## 先明确组件的运行方式

桌面小组件不是直接运行在 App 页面里的 Compose 界面。桌面启动器通过 Manifest 发现组件，再按 `AppWidgetProviderInfo` 提供的尺寸、初始布局、名称和预览信息创建它。界面通常由 `RemoteViews` 描述，用户操作通过 `PendingIntent` 发回应用。

因此要把组件当成一套跨越 Manifest、provider 配置、RemoteViews 布局、更新逻辑和启动器缓存的功能来开发。只写一个 Kotlin 类或 XML 布局并不完整。

## 容易做错的地方

### 1. 只改了一个地方的组件名称

只设置 `res/xml/*_widget_info.xml` 的 `android:label`，在部分启动器里名称仍可能显示成应用名、类名或旧名称。也不要把组件标题只画进预览图里：预览图中的文字只是图片，不是组件的系统名称。

正确做法是用字符串资源统一管理名称，并同时设置：

- 对应 `<receiver>` 的 `android:label`。
- 对应 `<appwidget-provider>` 的 `android:label`。

三个组件各自设置名称，不要共用一个含义不清的硬编码字符串。改完后检查最终 APK 的 Manifest 已合并了这些值，并在目标手机上更新安装、刷新或重新打开桌面的小组件列表。启动器可能缓存旧的组件信息；只看源码或只重新编译不能证明手机上的名称已经更新。不同厂商启动器的显示方式也可能不同。

### 2. 把应用图标当成组件预览图

应用图标表达的是“这是哪个 App”，预览图则要展示“这个组件放到桌面后长什么样”。用应用图标代替预览图会让组件选择器无法区分不同组件，也会误导用户。

每种组件都应有贴近真实桌面尺寸和内容的预览素材，并在配置中声明 `android:previewImage`。支持布局预览的系统版本还应提供 `android:previewLayout`，指向该组件真实使用的 RemoteViews 布局。预览资源、`initialLayout` 和运行时创建的 RemoteViews 应保持一致；不要只更新其中一个。

### 3. 只在模拟器或源码里检查

桌面启动器对最小尺寸、可调整尺寸、预览、名称和刷新时机的处理并不完全一致。构建成功只能说明 APK 能打出来，不能说明桌面识别和展示正确。

至少在目标手机验证：组件选择器里三个名称和预览是否正确；添加后尺寸、内容和点击区域是否合理；点击和左右切换是否生效；重启或升级后组件是否仍能恢复。名称或预览改动没有反映时，确认安装的是本次 APK，再刷新启动器的组件列表；仍旧过期时，可移除并重新添加组件，必要时重启启动器或手机。

### 4. 所有实例共用同一个 PendingIntent

Android 会按 Intent 的匹配规则复用 `PendingIntent`。如果多个组件实例使用相同 request code 和等价 Intent，点击一个组件可能拿到另一个实例的数据，或者更新标记互相覆盖。

每个实例的点击 Intent 应携带稳定且唯一的标识，例如 widget ID；需要区分动作时也要区分 action、data 或 request code。更新 `RemoteViews` 时，把正确的 widget ID 传入对应的 `PendingIntent`。使用 `FLAG_IMMUTABLE` 或 `FLAG_MUTABLE` 时要根据是否需要由系统填充数据来选择，通常普通启动和广播操作用 immutable 即可。

### 5. 把普通页面控件直接塞进 RemoteViews

`RemoteViews` 只支持一组有限的 Android View 和操作，不等同于普通 Activity 布局，也不能直接承载 Compose 页面、任意自定义 View 或完整的文本编辑体验。桌面上的快速输入框更可靠的实现是做成清晰的点击入口，点击后启动 App 的新建笔记页面。

启动编辑页时通过明确的 action 或 extra 表达“新建笔记”，让页面进入新建状态并自动请求输入焦点、弹出键盘。还要处理 Activity 已经存在时的新 Intent（例如 `onNewIntent`），否则从桌面再次点击可能只打开旧页面而没有开始新建。

### 6. 只在首次创建时更新内容

组件内容不是应用页面的实时视图。笔记新增、删除、收藏状态变化或漫步切换后，应明确调用相应 provider 更新实例；组件重新创建时也要能从持久化数据恢复。不要依赖过于频繁的周期刷新来保持同步，应由数据变更和用户操作触发更新。

每个组件实例自己的状态也要单独保存。例如不同漫步组件可以各自记住当前位置；不同收藏组件可以各自绑定一篇收藏。不要只按组件类型保存一个全局值。

### 7. 配置页没有遵守小组件配置流程

需要用户先选一篇收藏笔记时，应在 `AppWidgetProviderInfo` 声明配置 Activity。Activity 需要读取 `EXTRA_APPWIDGET_ID`，选择完成后保存该 ID 对应的数据，设置 `RESULT_OK` 并把 widget ID 放回结果 Intent。取消或无效 ID 应返回取消结果。遗漏这些步骤会出现选完不添加、配置错实例或添加流程卡住。

## 推荐的实现顺序

1. 为每种组件确定用途、最小尺寸、可调整方向、点击行为和空数据状态。
2. 创建独立的 RemoteViews 布局、名称、描述和预览素材；让预览布局尽量复用真实组件布局。
3. 在 Manifest 注册独立 provider receiver，并关联各自的 `AppWidgetProviderInfo`；名称同时设置在 receiver 和 provider 配置上。
4. 实现首次更新、数据变更更新、用户操作和重建恢复。按组件 ID 保存需要隔离的状态。
5. 对每个点击操作构造可区分的 Intent/PendingIntent，逐个验证动作不会串到其他实例。
6. 构建安装到目标设备，从组件选择器开始验证名称和预览，再添加到桌面检查实际尺寸、内容、点击和刷新。
7. 更新组件名称或预览后，确认设备装的是新 APK，并考虑启动器缓存；以实际目标启动器显示为验收依据。

## 随心记项目的对应关系

- 随机漫步：左右按钮只切换该组件实例当前展示的笔记，点击笔记正文打开对应笔记。
- 快速新建：桌面入口启动新建笔记流程；进入编辑页时直接获得焦点并打开键盘。
- 收藏笔记：添加后先显示“点击选择收藏文章”；点击组件进入 App 的收藏列表，选中文章后按 widget ID 保存并返回桌面。侧栏“收藏列表”可以浏览收藏；无收藏时显示“暂无收藏”。每个组件实例可以展示不同收藏。

实现位置主要在 `app/src/main/AndroidManifest.xml`、`app/src/main/java/com/qiuyinlan/suixinji/NoteWidgets.kt`、`app/src/main/res/xml/`、`app/src/main/res/layout/` 和 `app/src/main/res/drawable/`。改完这些资源后，要验证合并后的 Manifest 和手机上的实际组件列表，不能以源码中出现了名称或预览配置作为完成标准。
